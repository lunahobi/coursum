# ADR 0001: Приоритет Alembic в управлении схемой и миграции при запуске

## Статус

Принято

## Контекст

Изначально в системе были смешаны изменения схемы во время выполнения и запуск приложения. Это создавало риски:
- схема могла изменяться неявно при запуске сервиса
- поведение различалось для новой и уже существующей БД
- ухудшалась воспроизводимость демонстрации для защиты ВКР

## Решение

- Перенести эволюцию схемы полностью в Alembic-миграции.
- Использовать точку входа при запуске, которая применяет миграции до запуска приложения.
- Убрать побочные эффекты создания и исправления схемы из жизненного цикла приложения.
- Добавить защитное поведение с отметкой версии для существующей схемы без `alembic_version`.

## Последствия

### Плюсы

- детерминированная эволюция схемы
- более предсказуемый релиз и откат
- четкое разделение логики времени выполнения и миграций

### Компромиссы

- требуется дисциплина миграций для каждого изменения схемы
- запуск сервиса зависит от успешного применения миграций

## Рассмотренные альтернативы

1. Оставить исправление схемы во время выполнения
   Отклонено: слишком неявно и хрупко.
2. Применять миграции только вручную вне контейнера  
   Отклонено: выше риск операторских ошибок для текущего процесса разработки.

# ADR 0001: Alembic-first управление схемой и миграции на старте

## Статус

Принято

## Контекст

Изначально в системе были смешаны runtime-патчи схемы и старт приложения. Это создавало риски:
- схема могла изменяться неявно при запуске сервиса
- поведение различалось для новой и уже существующей БД
- ухудшалась воспроизводимость демонстрации для защиты ВКР

## Решение

- Перенести эволюцию схемы полностью в Alembic-миграции.
- Использовать startup-entrypoint, который применяет миграции до старта приложения.
- Убрать побочные эффекты создания/патча схемы из lifecycle приложения.
- Добавить guard/stamp-поведение для существующей схемы без `alembic_version`.

## Последствия

### Плюсы

- детерминированная эволюция схемы
- более предсказуемый релиз и откат
- четкое разделение runtime-логики и миграций

### Компромиссы

- требуется дисциплина миграций для каждого изменения схемы
- старт сервиса зависит от успешного применения миграций

## Рассмотренные альтернативы

1. Оставить runtime-патчинг схемы  
   Отклонено: слишком неявно и хрупко.
2. Применять миграции только вручную вне контейнера  
   Отклонено: выше риск операторских ошибок для текущего процесса разработки.

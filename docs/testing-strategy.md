# Стратегия тестирования

## Цели

- Защитить ключевые обучающие сценарии от регрессий.
- Сделать проверяемыми гарантии изоляции организаций и ролевого доступа (RBAC).
- Проверять критичные UI-потоки через детерминированные браузерные тесты.

## Слои тестирования

### Модульные и интеграционные тесты серверной части (Pytest)

Покрывает:
- авторизацию, ролевой доступ и границы организаций
- API по курсам/урокам/тестам/практикам
- адаптивную логику и генерацию рекомендаций
- конечную точку аналитики

Команда:

```bash
python -m pytest backend/tests -q
```

### Модульные и интеграционные тесты веб-панели (Vitest + RTL)

Покрывает:
- отображение и взаимодействия на уровне страниц
- обработку API-состояний
- поведение панели показателей и аналитики

Команда:

```bash
cd web
npm test
```

### Базовые сквозные проверки интерфейса (Playwright)

Покрывает:
- страницу входа и сценарий авторизации
- навигацию по основным страницам панели преподавателя и администратора
- отображение сводки активности на панели показателей

Команда:

```bash
cd web
npm run test:e2e
```

## Отчетность

### Результаты API-тестов в Allure

```bash
python -m pytest backend/tests --alluredir allure-results/api -q
```

### Результаты тестов интерфейса в Allure

Формируются отчетным модулем Playwright в `allure-results/ui`.

### Общий отчет API + UI

```bash
cd web
npm run allure:all:generate
npm run allure:all:open
```
